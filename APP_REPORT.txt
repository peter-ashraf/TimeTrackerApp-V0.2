# TimeTracker App Report

Generated: 2026-06-09

## Executive Summary

TimeTracker App V0.2 is a React 18/Vite single-page application for employee time tracking, pay-period management, overtime calculation, leave tracking, exports, reminders, offline use, and Supabase-backed sync. The codebase is more ambitious than a simple tracker: it includes PWA support, encrypted local storage, background sync, conflict handling, password reset, local/offline fallback authentication, and GitHub Pages deployment configuration.

The production build succeeds, which is a strong baseline. The main risks are not basic build breakage; they are correctness, maintainability, security posture, and runtime reliability around sync/auth/offline behavior. Several areas show signs of rapid iteration: duplicated sync utilities, stale or corrupted documentation text, broad context files, inline styles, console/debug traces, and at least one likely UI event-handler defect.

## Key Findings

### 1. Likely Touch Navigation Bug

In `src/App.jsx`, `handleTouchEnd` is assigned to the return value of `useEffect`:

- Definition: `src/App.jsx:360`
- Usage: `src/App.jsx:852`

`onTouchEnd` expects an event handler function, but `useEffect` returns `undefined` unless its effect returns cleanup logic. This means horizontal swipe completion is likely broken or inconsistent. The resize logic inside that effect is useful, but it should be separate from a real `useCallback` touch-end handler.

Impact: mobile swipe navigation may not complete correctly.

Priority: high.

### 2. Documentation Mentions a Client-Side Service Role Key

The README lists:

- `VITE_SUPABASE_SERVICE_ROLE_KEY=your_service_role_key`

Any `VITE_` environment variable is exposed to client-side code at build time. Supabase service-role keys should never be shipped to browsers.

There is also a local utility reference:

- `src/utils/databaseVerification.js:8`

That file reads `process.env.VITE_SUPABASE_SERVICE_ROLE_KEY`. Even if not bundled into the app today, the naming encourages unsafe configuration.

Impact: serious security risk if a real service role key is ever placed in a Vite-exposed environment variable.

Priority: high.

### 3. Sync Architecture Is Powerful but Complex

The app has multiple overlapping sync/offline paths:

- `src/utils/backgroundSync.js`
- `src/utils/backgroundSync-enhanced.js`
- `src/utils/offlineQueue.js`
- `src/hooks/useOfflineQueue.js`
- `src/hooks/useInstantData.js`
- local encrypted storage helpers
- cache manager
- Supabase data helper
- multi-tab sync

The feature set is valuable, but the number of paths makes it harder to prove which source of truth wins in edge cases. For example, local saves, cache updates, remote fetches, conflict prompts, deleted remote entries, and offline-created entries all interact in `TimeEntryContext`.

Impact: higher risk of duplicate entries, lost edits, stale cache, or surprising conflict prompts.

Priority: medium-high.

### 4. Data Deletion Depends Heavily on Local Entry IDs

`supabaseData.deleteTimeEntry` requires an `id` and returns `missing_id` when it is absent. `TimeTrackerContext.deleteEntry` tries to resolve an ID from the server if missing, but the lower-level delete helper itself does not support deletion by `(user_id, date)` even though the table appears to use `user_id,date` as an upsert conflict key.

Impact: entries can become hard to delete if local state loses the remote ID.

Priority: medium-high.

## Risks and Issues by Area

### Reliability

- The touch-end handler issue should be fixed first for mobile UX.
- Background sync has multiple implementations/import paths, increasing drift risk.
- Some async operations intentionally continue in the background without awaiting all results, which can be fine but needs user-visible sync state.
- Deletion edge cases can fail when entry IDs are absent.
- Conflict resolution compares serialized interval JSON, which can detect differences but may be sensitive to object shape/order.

### Security and Privacy

- Remove all references to Vite-exposed service-role keys.
- Audit `.env` handling and make sure only publishable Supabase keys are used in browser code.
- Local "simple encryption" should be treated as obfuscation unless its key handling and threat model are documented.
- Rate limiting in localStorage helps UX but is not a security boundary.
- Offline/failsafe auth needs careful documentation because local-only authentication can create user expectations that differ from Supabase-backed auth.

### Performance

- Production bundle is acceptable for a feature-rich app, but export/PDF/XLSX chunks are large.
- PWA precache size is close to 5 MB. This may be acceptable, but every added asset will make updates heavier.
- Static and dynamic imports are mixed for the same modules, limiting chunking benefits.
- Cache invalidation/versioning should be periodically reviewed because stale local data is a major risk in offline-first apps.

### Maintainability

- Context providers are large and own many responsibilities.
- Some logic is duplicated between `App.jsx`, `TimeEntryContext`, `TimeTrackerContext`, and utility modules.
- There are multiple CSS files and inline style islands.
- Documentation is out of sync with the repo.
- There is no lint/test safety net.

### UX and Accessibility

- Modals and status indicators are present, which is good.
- Mobile gestures are intended, but the touch-end bug may degrade them.
- The app would benefit from systematic keyboard/focus testing on modals, selects, and conflict resolution.
- Save/offline/conflict states should be clear enough that users know whether data is local-only, queued, synced, or conflicted.

## Overall Assessment

The app is functional and thoughtfully equipped for real usage: it handles time tracking, payroll-adjacent calculations, offline persistence, cloud sync, reminders, exports, and account recovery. The build passing suggests it is in a workable state.

The next stage should focus less on adding new features and more on reducing complexity. The best payoff will come from fixing the mobile handler bug, removing unsafe service-role-key guidance, writing tests for the calculation engine, and simplifying the sync/offline architecture into one clearly documented flow.
